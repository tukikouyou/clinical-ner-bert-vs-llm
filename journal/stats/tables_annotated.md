# 全対照表（考察・用語付き）

元の表は `stats/tables.md`（自動生成、こちらは手を加えない）。本ファイルは同じ表に用語説明と考察を加えたもの（`code/annotate_tables.py` で生成）。

## 用語

- **test36**：iCorpus fold 0 のテスト 36 文書・433 文。全モデル同一。
- **relaxed F1**：LAU 論文と同じ部分一致指標。型が一致し、かつ一方の表層が他方の部分文字列なら正解。文ごとに貪欲法で 1 対 1 対応（v2 では予測は列挙順、正解は出現位置順、完全一致を優先する決定的規則）。マイクロ平均。
- **strict F1**：完全一致。型と NFKC 正規化後の表層が完全に等しい場合のみ正解。境界まで含めた厳密な性能。
- **95% CI / 文書ブートストラップ 2000 回**：テスト 36 文書を再標本化単位として、復元抽出で 36 文書を 2,000 回引き直し、各回の F1 の 2.5/97.5 パーセンタイルを区間とする。対差（pairwise）は同じ再標本で両モデルの F1 の差を取る「対応あり」版。区間が 0 を跨げば差は検出できない。
- **min2 / min3**：relaxed の照合で、部分文字列側に最小長 2 文字 / 3 文字を課した値。1 文字の断片（「瘤」「後」など）との対応を正解に数えない、relaxed と strict の中間の指標。
- **Macro**：テスト集合に 20 件以上出現する 48 ラベルの F1 の単純平均。頻度の高いラベルに引っ張られない指標。
- **-others統合**：ラベル末尾の -patient / -others の区別を無視して再集計した relaxed F1。元の F1 との差が「主体の取り違え」に起因する誤りの上限。
- **exact/TP**：relaxed で TP と数えた対のうち、表層が完全一致していた割合。1 に近いほど境界の取り方が正解と一致している。
- **截断/433**：433 文のうち生成が最大生成長（FT 推論は 900 トークン、ZS 思考型は 3,072）に達して打ち切られた文数。打ち切られた文は後半のエンティティが欠け、再現率を下げる。
- **parse失敗**：出力から JSON 配列を取り出せず、その文の予測を空（正解すべて FN）とした文数。
- **未知ラベル**：ラベル一覧 109 種にない型を出力した予測の個数（FP に数える）。制約デコードでは定義上 0。
- **prompt-only (v1) / parser v1**：LAU 論文と同じ条件。プロンプトで JSON を要求するだけで、出力の最初の `[` から最後の `]` までを JSON として読む旧パーサ。思考文中の `[` に引っかかって失敗しやすい。
- **prompt-only (v2) / parser v2**：推論は同じ生出力を、新パーサで読み直した値。Harmony 形式なら最後の final チャネル以降だけを見て、右端から探して最初に正しく読めた `[{label,text},…]` 配列を採用し、打ち切りなら閉じた要素まで修復。評価側の欠陥を除いた「本来の」ZS 値。
- **制約 F1 / 整段制約**：vLLM の JSON Schema 制約デコード（xgrammar、任意空白禁止）。出力全体を `[{"label": <109 種の enum>, "text": <文字列>}, …]` に制限する。思考型モデルも思考を含め出力全体が制約される。
- **2段階 (think→constrain)**：思考型モデル用の 2 パス。1 パス目は prompt-only と同じ自由生成で思考文（Harmony の analysis、SIP は自由文）を得て保存、2 パス目でその思考文をプロンプトに戻し、回答部分だけを JSON Schema 制約で生成する。vLLM 新版の「reasoning parser + 回答のみ制約」と等価の代替。
- **strict (2段階)**：2 段階条件の strict F1。
- **参考モデル**：ollama で動かした Qwen3.6-35B と GPT-OSS-120B。QLoRA 学習ができないため ZS の参考値のみ。
  - **ZS prompt-only (think=false)**（Qwen3.6）：思考を切った通常生成。ollama では think=false だと format（schema）が無視されるため「think=false + 制約」は作れない。
  - **think=true + 制約**：思考を許可し、回答部分に JSON Schema を適用（ollama の format は思考部には掛からない）。思考が num_predict 予算を食い潰すと回答が空になる。
  - **GPT-OSS-120B の ZS prompt-only (think=true; 無効化不可)**：GPT-OSS は ollama で think=false を受け付けず常に思考する。したがってこの行は「思考あり・制約なし」、次の行「think=true + 制約」は同じ思考ありに**制約だけを足した**条件。2 行の違いは制約の有無だけ。
