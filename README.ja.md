# 日本語臨床NER：ファインチューニングBERT vs. ゼロショット／ファインチューニングLLM

[English](README.md) | **日本語** | [中文](README.zh.md)

日本語臨床テキストに対する固有表現抽出(NER)。**ファインチューニングした
BERTエンコーダ**と**大規模言語モデル(LLM)**（ゼロショットおよび QLoRA ファインチューニング後）を、
同一の gold アノテーション付きコーパス上で、統一した評価手順で比較する。

本プロジェクトの目標は3つ:

1. **精度比較** — BERT(UTH-BERT, NICT-BERT)と 9 種の LLM(LLM-jp, SIP-jmed, Gemma/MedGemma,
   Qwen, Llama/Med42)のNER精度を、公開アノテーション済みコーパスで測定する。
2. **実データ抽出** — 同じパイプラインを実臨床レポートに適用する。
3. **FHIR抽出**（予定） — 臨床レポートからFHIRにマッピング可能な項目を抽出する。

> ⚠️ **本リポジトリに臨床データは一切含まれません。** 学習・評価コーパス
> (iCorpus / 症例報告コーパス)は研究目的限定のライセンスで再配布不可であり、
> 実臨床レポートは患者データを含みます。本リポジトリには**コードと集計指標
> (数値とラベル名のみ・本文なし)**だけを収録しています。[データ](#データ)を参照。

## 結果（論文誌版、2026年10月）

設定：iCorpus（113 種のエンティティ型）、学習 146 文書／テスト 36 文書（433 文、正解 12,919 個）。
全 LLM で同一のプロンプトと QLoRA 設定。決定的な 1 対 1 対応付けを **relaxed**（型が一致し一方の表層が
他方の部分文字列）と **strict**（型と NFKC 正規化後の表層が完全一致）の F1 で評価、文書単位ブートストラップ CI、
**3 seed** のファインチューニング、**JSON Schema 制約デコード**と思考型モデル用の 2 段階「自由思考→制約回答」、
SIP-jmed-13B と MedGemma-27B の**基盤モデル**。コード・run メタ・統計・図は [`journal/`](journal/)。
LAU-16 の単一 seed の結果は下表で置き換える。

主な知見：

- ゼロショットでは全 LLM がファインチューニング済み BERT を大きく下回る（relaxed F1 ≤ 0.32 vs. 0.75）。
  これは出力形式の問題では**ない**：制約デコードで parse 失敗と体系外ラベルは 0 になるが F1 は最大 0.02 しか
  動かず、思考型モデルの最良（自由思考＋制約回答）でも 0.17。思考型の「parse 失敗」の大半は旧パーサ
  （最初の `[` … 最後の `]`）の欠陥だった。
- QLoRA 後は全 LLM が BERT を上回り、13B 以上は同等（relaxed 0.815–0.827、strict 0.779–0.798；seed 間 SD ≤ 0.006
  でモデル間差より大きい）。LLM と BERT の差は strict（+0.10）のほうが relaxed（+0.07）より大きい。
- 基盤モデルを揃えると**医療事前学習の効果は検出できない**（3 対 × 3 seed、対差はすべて ±0.005 以内で区間は 0 を含む）。
- 残る取りこぼしは、JSON 出力が 900 トークン上限を超える約 20% の文（正解の 52% を含む；再現率 0.58 vs. 他 0.92）と
  患者以外が主体のラベル（`-others`）に集中する。

## 手法

### BERT（ファインチューニング）

`BERT-CRF` = 事前学習BERTエンコーダ + 線形ヘッド + CRF。2つのエンコーダ:

- **UTH-BERT** — 日本語臨床テキストで事前学習(語彙25k; MeCab ipadic-neologd +
  万病辞書(J-Medic) + 数字分割 + WordPiece)。
- **NICT-BERT** — 日本語Wikipediaで事前学習(語彙32k; MeCab Juman辞書 + WordPiece)。

文字レベルのエンティティアノテーションを、`difflib`で文字スパンをサブワードに
対応付けてCoNLLへ変換する([`bert/build_conll.py`](bert/build_conll.py))。
エンティティ被覆率は 95.7%(UTH) / 99.7%(NICT)。ファインチューニングはAdamW、
検証F1での早期終了。

> **CRFの落とし穴:** CRFは不正なBIO遷移(`O→I-x`, `B-x→I-y` …)に−1e7のペナルティを
> 与える。投入するIOBは厳密に正しいBIOでなければ、F1は正常なまま損失が爆発
> (〜1e8)する。`build_conll.py`にBIO修復処理を含む。

### LLM（ゼロショットとファインチューニング）

各文を、109 ラベルを列挙し JSON 配列 `[{"label","text"}]` を要求する 1 つのプロンプトに入れる
（`journal/code/eval_v2.py`、vLLM、貪欲デコード）。条件：プロンプトのみ；JSON Schema 制約デコード
（`--guided`、XGrammar、ラベルを体系内に限定）；思考型モデルは 2 段階「自由思考→制約回答」（`--think_from`）；
QLoRA ファインチューニング（`journal/code/qlora_train_v2.py`：NF4、LoRA r=16、3 epoch、seed 42/1/2）後は
adapter を付与または併合して推論。参考モデル 2 種（Qwen3.6-35B、GPT-OSS-120B）は ollama で実行。

### 評価

BERT の予測と LLM の出力を文ごとの `(型, 表層)` に変換し `journal/code/metrics_v2.py` で採点する：
決定的な 1 対 1 貪欲対応付け、**relaxed**（型が一致し一方の表層が他方の部分文字列、NFKC）と
**strict**（表層が完全一致）の F1、最小長・主体統合・マクロの各変種、文書単位ブートストラップ CI と対差。
`llm/testset_eval.py` は LAU-16 版の採点器（relaxed のみ、集合の走査順に依存）。

## データ

**含まれません。** 再現には以下が必要:

- **iCorpus（症例報告コーパス）** — アノテーション付き症例報告コーパス
  (183文書、文字レベルエンティティ)。研究目的限定ライセンス。東京大学
  (医療AI開発学講座)から入手し、`corpus/icorpus_.../data/json/`に配置。
- **UTH-BERT** — https://ai-health.m.u-tokyo.ac.jp/home/research/uth-bert
- **NICT-BERT** — https://alaginrc.nict.go.jp/nict-bert/
- **万病辞書**(J-Medic) — UTHトークナイズ用。
- 抽出ステップ用の実臨床レポート(各自の患者データ)。

## セットアップ

```bash
# BERTパイプライン(システムPython)
pip install torch==2.0.1 transformers==4.46.3 seqeval pandas mecab-python3 jaconv neologdn
# + MeCab辞書: mecab-ipadic-neologd(UTH), mecab-jumandic-utf8(NICT)

# LLM評価(別venv)
pip install "vllm==0.8.5" "transformers==4.51.3" pandas requests
# + ollama (Qwen/Llama/GPT-OSS用)
```

### 実行

```bash
# 1) コーパスから学習データを作成
python bert/build_conll.py

# 2) ファインチューニング(エンコーダ別)
python bert/NER_training.py --bert_type UTH  --bert_path <UTH-BERT>  --data_path data/csv/icorpus_UTH.csv  --patience 15
python bert/NER_training.py --bert_type NICT --bert_path <NICT-BERT> --data_path data/csv/icorpus_NICT.csv --patience 15

# 3) BERT vs LLM 精度比較
python llm/testset_eval.py                                   # BERTベースライン
python llm/testset_eval.py --model qwen3.6:35b --engine ollama --hosts <urls>
python llm/testset_eval.py --model <hf-model> --engine vllm --tp 2

# 4) 実レポートから抽出
python bert/predict_reports.py --bert_type UTH --model_path <model.pt> --data_dir <reports> --out_dir <out>
```
